01背景

按品线管理产品规格书字段，减少不同产品资料格式不一致、字段配置重复维护、版本选择不清晰的问题。需求依据为用户提供的 2026-11-02 原型包，未提供真实用户调研或业务基线。

此页是根据原型源码整理的产品方案，不代表已上线系统。配置数据、人物及品线示例均为演示；页面中的发布仅改变本浏览器演示状态。

02目标

  • 用户目标：模板可复用、字段可编辑、发布版本可选择，配置结果可直观预览。
  • 交付目标：从原型总览可搜索、进入、编辑、保存及返回；方案与原型在同一入口可查阅。
  • 建议验证指标：配置任务完成率、从新建到发布的耗时、字段校验失败率；基线与目标值需试用后制定，不编造提效比例。

03用户角色

角色任务当前边界
品线／配置管理员维护一级模板、二级品线及版本原型不区分账号和操作权限
产品资料填写人员按已发布版本填写规格信息仅联动预览，不提交实际产品数据
产品、设计、研发、测试评审交互、字段规则及验收正式权限与审批链待确认

04使用场景

  1. 一级品线已形成通用规范，需要建立或修改默认字段模板。
  2. 新增二级品线，自动继承模板生成 V1.0 草稿，并补充差异化字段。
  3. 已有规格要求变化，复制或新建版本，不直接改动已发布版本。
  4. 上线前通过联动预览检查不同品线和版本对应的填写表单。

05功能范围

本期做 · P0

  • 接入总览的物料库分类、关键词搜索和内嵌查看。
  • 保留品线筛选、模板继承、字段配置及排序。
  • 保留版本创建、复制、发布、默认版本选择。
  • 保留浏览器本地保存与前端联动预览。
  • 提供产品方案入口及源码定位。

本期不做

  • 真实后台服务、登录、多人协作。
  • 生产规格书提交、导出和历史数据迁移。
  • 发布审批、生产审计、权限强制校验。
  • 在线代码编辑器或全新拖拽画布。
  • 对旧业务原型进行无关重构。

06业务流程

编辑一级模板→保存模板→新增二级品线→继承 V1.0 草稿→配置并校验→保存／发布→前端预览
  • 快照继承：创建时复制模板字段；后续一级模板变化不覆盖已有二级版本。
  • 版本修改：草稿可修改；发布后只读，需新建或复制版本继续调整。
  • 默认版本：首次发布且没有默认版本时自动设为默认；之后只能从已发布版本中选择默认。
  • 终止与分支：字段校验不通过时阻止保存／发布并提示；关闭有未保存变更的配置时提供确认；取消新建不生成记录。

07功能说明

模块入口与正常行为状态与异常
总览物料库分类或搜索“规格书”进入；查看器支持返回、独立打开、产品方案和源码位置检查入口资源，加载中显示提示；失败可重试；返回保留总览搜索与分类
品线列表展开一级品线，搜索、按品线和配置状态筛选，新增二级品线无匹配数据提示并可重置；新增名称为空、超长或同一级下重名时阻止提交
字段编辑基础信息、产品主要部件、产品性能、安规重要零件四个模块；编辑名称、标识、类型、必填、选项、默认值和顺序发布版本只读；草稿错误需修正；修改仅在保存成功后持久化
版本管理创建、复制、编辑草稿、发布和设置默认版本重复版本号或格式不合法阻止创建；草稿不能设为默认
联动预览选择一级、二级品线和已发布版本，展示动态表单没有已发布版本时显示空态；草稿不出现在前端可选版本中；不提交真实数据

响应式边界：保留原型原有桌面配置布局；本期不承诺手机端完整字段编辑体验。产品方案适配窄屏，表格可横向浏览；正式移动端需求需单独确认。

08数据规则

对象／字段原型当前规则
二级品线名称去除首尾空格，必填，最多 40 字符；同一级下不允许大小写不敏感的重名
品线编码一级编码加递增三位序号；不接入真实主数据
版本号／名称版本号格式 V数字.数字，统一大写，同二级品线内唯一；名称去空格后必填
字段名称／标识名称不能为空；标识以英文字母开头，仅含字母、数字、下划线；同一版本内忽略大小写后唯一
控件类型单行文本、多行文本、数字、下拉单选、下拉多选、日期；类型和模块需在预定义集合中
可选值／默认值选项支持中英文逗号、分号或换行分隔并去重；选择类至少一个选项，默认值需属于选项；数字默认值须有效，日期须为有效 YYYY-MM-DD
字段数量一套配置至少包含一个字段；不要求四个模块都必须有字段
存储localStorage：starmerx-spec-field-studio-v1；同浏览器、同 origin 保存后刷新保留，清除浏览器数据会丢失；不同端口／浏览器不互通
源文件编辑与浏览器业务配置不是一回事：页面“保存”不回写 app.js。原压缩包单文件 HTML 是导入快照，总览持续维护分离源码版。

09权限规则

原型现状 无登录、无角色隔离、无服务端鉴权。已发布只读是交互规则，不是安全控制；请勿录入敏感或真实业务资料。

正式落地建议 · 待确认 配置管理员维护模板和草稿；发布权限独立控制；填写人员仅选择授权范围内的已发布版本。接口应重新校验权限、版本归属及状态，防止绕过前端修改。是否需要发布审批、组织隔离与审计留痕由业务确认。

10埋点需求

以下仅为建议，当前未接入埋点或向外部发送数据。

建议事件名触发时机属性与指标
spec_config_open进入配置入口、对象 ID；配置访问次数

12风险与待确认问题

  • 主数据归属：一级／二级品线与真实主数据系统如何映射，谁有新建权限。
  • 发布治理：谁可发布，是否审批，是否支持停用、撤回及替换默认版本。
  • 历史实例：建议已填写规格书绑定版本 ID 和快照；本期未实现真实实例，不能宣称已有兼容保证。
  • 并发与幂等：真实后端需处理版本唯一性、并发保存、发布重复提交，原型不具备多人一致性能力。
  • 数据恢复：浏览器存储不是备份；正式方案需导出、备份、迁移和审计策略。数据损坏时原型可能回到演示初始数据。
  • 上线与回滚：当前仅本地接入；上线需先确认权限、API、数据库及迁移策略。本期撤销入口可移除该目录注册和五项资源映射，不必删除本地保存数据。
  • 验证范围：接入结果以实际测试记录为准；产品规则建议不等于已实现功能。
